# Решись Авиа — прогноз спроса

Реализован вариант A: консольный скрипт. Дополнительно строится квантильный график спроса в SVG. Python 3.10 или новее; сторонние библиотеки для приложения не нужны.

## Запуск

Из папки проекта:

```sh
python3 forecast.py --from MOW --to AER --date 2026-06-12 --price 9000 --chart demand.svg
python3 forecast.py --from MOW --to LED --date 2026-06-20 --price 5500 --json
python3 -m unittest -v
```

Откройте demand.svg в браузере для просмотра графика. Работает без доступа к интернету.

Маршруты: MOW-AER (Сочи), MOW-LED (Санкт-Петербург), MOW-KGD (Калининград), MOW-OVB (Новосибирск), MOW-MRV (Минеральные Воды). Даты: 1 июня — 1 июля 2026 включительно. Цена в рублях.

## Расчёт

Находим ровно одну строку по маршруту и дате. Для каждого квантиля:

`demand = X_base_demand - price_sensitivity * (price - base_price)`

Простой прогноз берёт квантиль 0.5. Продажи:

`sales = min(seats, max(0, demand))`

Число мест берётся из данных; остаток — `seats - sales`. Это остаток после прогнозных продаж, не информация о фактических бронях. Прогноз дробный, потому что это модельная оценка; намеренно не округляем его до расчёта ограничения кресел.

При нулевой цене возможна полная загрузка; при очень высокой цене продажи обнуляются. Неизвестный маршрут, неверная дата, отрицательная/бесконечная цена и отсутствие рейса дают понятную ошибку. Ввод цены вне диапазона оптимизации разрешён для исследования формулы с предупреждением об экстраполяции.

## График

Горизонталь — спрос до ограничения по местам; вертикаль — накопленная вероятность (квантильная кривая). Девять точек — квантили 0.1–0.9, соединение служит визуальной интерполяцией. Между соседними точками по модели 10% вероятности. Неизвестные хвосты по 10% не дорисованы. Отмечены медиана и число мест. Медиана совпадает с `demand` простого прогноза, включая отрицательное значение при экстремальной цене; продажи всегда ограничены снизу нулём. Точная плотность из девяти квантилей не восстанавливается.

## Данные и ИИ

`data/my_forecast.csv` — собственный прогноз из ML-блока; `data/routes.csv` — исходный справочник кейса. Чтобы использовать другой прогноз: `--forecast путь/к/файлу.csv`.

Код подготовлен с помощью ИИ-ассистента Codex (семейство GPT-6); инструменты — Python, AutoGluon TimeSeries, CatBoost/статистические модели, локальный запуск и unittest. Фактически выбранная модель и измеренные метрики записаны в соседнем ml_metrics.json и в выполненном ноутбуке. ИИ помог написать код, разобрать ограничения и подготовить объяснения; численные результаты получены запуском расчётов.

Выбран вариант A, поэтому регистрации, авторизации, веб-интерфейса и размещения на хостинге в проекте нет. Это завершённый допустимый вариант решения, а не вариант B/C.
